# Безопасное обновление темы «Культура Неона»

## Правила
1. Изменения WordPress-темы готовятся в отдельной ветке, не в `main`.
2. Для каждого изменения открывается Pull Request с описанием и проверкой файлов.
3. Владелец сайта проверяет изменения и только затем сливает Pull Request.
4. На рабочий WordPress файлы не отправляются автоматически. Установка обновлённой темы — отдельное действие после одобрения.
5. Не хранить в репозитории пароли, ключи WordPress, API-токены, данные покупателей или резервные копии базы.
6. Перед обновлением PHP-шаблонов сохранять резервную копию сайта и проверять тему на тестовом сайте.

## Что ещё нужно настроить владельцу
- Защитить ветку `main` в GitHub: запрет прямых изменений, требование Pull Request и проверки.
- Для строгого разграничения доступа создать отдельный репозиторий только для темы и выдать права лишь к нему. В текущем репозитории папочные права не изолированы.
- При необходимости подключить деплой только после одобрения, с ограниченным доступом к каталогу темы, без доступа к базе данных и заказам.

**Важно:** этот файл описывает процесс, но сам по себе не включает защиту ветки и не создаёт технических ограничений прав.
